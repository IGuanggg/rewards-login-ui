界面已恢复为用户截图对应的原版：五张彩色统计卡片、底部悬浮导航、原工作台布局和设置表单。所有 `public/` 文件与基线 `518f7de` 一致。

本次只保留浏览任务积分漏显示的后端修复：完成日志中的 `offerId` 与 `pointsGained` 按同一轮、账号、平台去重汇总。重复活动不重复计分；零积分显示 0，未上报仍显示「—」。首页与整轮总数继续使用上游汇总。

首次打开记录库会新增去重表，并补回保留日志中有明确证据的历史分项。日志已裁剪时可能只能恢复部分收益。升级不改动原有任务状态、时间及整轮积分。

## 部署

使用 `rewards-points-fix-original-ui-20261026.zip`，不要使用上一版界面更新包。新包仅含 `lib/activity-store.mjs` 及本文档，不含前端、凭据、会话、Dockerfile 或 Compose 配置，适用于截图中的原版项目。

1. 等签到和人工授权结束，在服务器现有项目目录停止容器、备份数据与待覆盖源码。以下按服务名 `rewards`、数据目录 `data/` 举例；自定义挂载使用实际路径。

   ```bash
   docker compose stop rewards
   stamp=$(date +%Y%m%d-%H%M%S)
   tar -czf "../rewards-data-$stamp.tgz" data
   tar -czf "../rewards-points-$stamp.tgz" lib/activity-store.mjs
   ```

   数据备份含凭据和会话，请保存在私有位置。停机后复制整个数据目录，不要遗漏 SQLite WAL 文件。

2. 将新包解压覆盖到项目根目录，保留原 Dockerfile、Compose 和配置，再按原部署方式重建。

   ```bash
   docker compose up -d --build rewards
   docker compose logs --tail=60 rewards
   ```

3. 打开「任务记录」，确认有明确完成日志的浏览任务显示积分。没有明确证据时显示「—」是正常的。不需要重新授权账号，界面布局不会变化。

若构建失败且旧镜像尚在，可用 `docker compose up -d --no-build rewards` 恢复旧容器。若需回退代码，停机后从源码备份恢复 `lib/activity-store.mjs` 再重建。新增表不影响旧代码，普通回退无需覆盖更新后产生的数据。
