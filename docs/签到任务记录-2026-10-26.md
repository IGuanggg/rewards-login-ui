# 签到任务记录 · 2026-10-26

刷新网页后进入「运行日志」→「签到任务记录」，也可以在首页点击「查看任务记录」。首页的一键运行按钮会保留在工作台显示进度，运行记录自动跟随最新一轮。

## 能看到什么

- 日期筛选、当天签到轮次、任务明细数量、脚本汇报的已获积分和需要关注的记录。
- 每轮的开始时间、运行时长、结果、账号积分变化。
- 按账号、平台和类别汇总的每日任务、每日签到、阅读、Bing 搜索、浏览、集章等任务。
- 任务的最新说明及结果：执行中、已执行、已完成、此前已完成、已跳过、失败、部分完成、未确认完成或已终止。
- 每轮独立的原始日志，可按级别筛选，分页查看更早输出。查看旧日志时不会被实时刷新跳回最新页。

下面原来的日志区域已明确命名为「账号授权日志」，用于查看微软账号的人工授权过程。

## 记录规则

记录直接来自签到子进程输出，使用固定版本上游自带的日志解析器识别账号和积分。任务归类按实际日志内容判定；“Finished processing”只标为「已执行」，不会一概声称所有活动成功。有错误或缺少完成证据时保留异常状态。

积分总数使用上游的账号/整轮汇总。任务积分只在有明确任务汇总时显示，避免把逐项积分和最终合计重复相加。「—」表示没有明确汇报，而不是零积分。一次 Bing 搜索任务的多次查询归为同一类别，逐次查询可在原始日志里查看。

按配置时区及该轮开始日期归档；跨午夜的一轮继续归在启动当天。保存最近 30 个日期，每轮最多保留约 20,000 行原始输出，任务汇总单独保留。原始日志每页 200 行，不会一次把整个月日志加载到浏览器内存。

容器重新启动后，未结束的旧记录标为「记录中断」；异常退出后停止更新心跳的记录也会在约 90 秒后标明中断。功能不把进程退出码为 0 当作所有任务都成功。

## 数据位置及资源

数据保存在挂载目录的 `data/activity.db`，附带 SQLite WAL/SHM 文件；权限为 0600，接口沿用面板鉴权。日志写入前隐藏常见密码、Token、Cookie 和授权码，仍应将整份运行数据视为私人管理数据。

没有增加数据库容器或常驻日志服务。页面可见时约每 3 秒读取少量数据，离开记录页或页面不可见时停止轮询。原来的 1.5 GiB 容器限制保留。

该采集入口位于内置 Docker 启动器，覆盖面板和内置定时任务启动的签到。绕过启动器直接运行上游脚本、或连接另一台未经适配的外部 Control API，不会自动写入此记录库。若修改上游设置使大部分信息日志不输出，能识别的任务明细也会减少。

## 验证

- 本地 42 项自动化检查通过：10 项记录及接口检查、5 项 Docker 检查、27 项原面板回归。
- 服务器镜像构建时通过可见/无头浏览器、noVNC、真实上游解析器和完整 worker 生命周期检查。
- 模拟的三类任务及 18 积分仅写入隔离的临时测试库，没有写进生产记录，也没有运行真实 Rewards 签到。
- 生产接口鉴权通过，数据文件已落在 `/data`，原有账号保留。
- 部署时确认没有正在运行的授权或签到任务。

功能从启用后的下一轮签到开始保存。部署时生产记录为空，不会补造之前的任务明细；真实账号积分和最终任务结果仍以随后运行的脚本汇报为准。
