# Docker 授权窗口修复记录 · 2026-10-26

服务器：`192.168.1.45:4173`。只修改并重建 Rewards 面板服务，原账号配置保留。

## 故障原因

面板访问密码验证正常；微软账号授权任务在启动约半秒后退出，尚未进入人工登录等待流程。日志为：

```text
[runtime] websockify: spawn websockify ENOENT
[ERROR] Service on 6080 exited before readiness
```

容器中 `/usr/bin/websockify` 文件存在，但它的 shebang 指向的 `/usr/bin/python3` 不存在。`dpkg --audit` 同时报告多项 Python/noVNC 包未配置完成。

服务器使用了离线版本 Dockerfile，通过 `dpkg -i` 批量安装 deb 包，再用 `|| true` 忽略安装和配置错误。Python 的依赖及预依赖没有正确安装，镜像却仍然构建成功。

## 修改

- 在服务器备份原 Dockerfile，保留镜像源、npm 镜像和预置浏览器配置。
- 离线依赖改由 APT 按依赖顺序安装，取消吞掉错误的逻辑；该安装步骤禁用网络，并禁止删除包。
- 构建时检查 `dpkg --audit` 为空，确认 Python 能导入 websockify。
- 构建时实际运行 `docker/smoke.mjs`，验证可见 Chromium、无头 Chromium、Xvfb、x11vnc 和 noVNC。失败时阻止生成新镜像。
- 重建镜像后只重建 `rewards` 服务，保留挂载的数据目录。部署后的镜像标识为 `30046adc8715…`。
- 本地通用 Dockerfile 同时显式安装 Python，并加入构建阶段的浏览器自检。

服务器离线安装步骤的核心命令：

```dockerfile
RUN --network=none apt-get --fix-broken --no-install-recommends --no-remove -y install /opt/debs/*.deb \
    && test -z "$(dpkg --audit)" \
    && python3 -c "import websockify" \
    && rm -rf /opt/debs /root/.npm
```

## 接下来如何使用

刷新网页并重新进入面板，点击账号「连接」→「启动浏览器授权」→「打开远程浏览器」。需要同时连接手机和电脑时，选择「两端都授权」。在远程窗口中完成微软登录及二次验证，回到面板确认各平台的会话已写入。

本次没有输入微软密码、没有完成微软账号登录，也没有运行签到。测试授权由排查程序主动终止，因此测试记录中的 cancelled 属于预期结果。最终会话写入仍需用户完成微软验证。
