## 二、逐条修复说明

### 1. 面板访问鉴权（P1）

- 面板现在有自己的访问密码：首次启动生成随机密码写入 `config.json`（0600）并打印在终端，也可用 `PANEL_TOKEN` 指定。
- 除 `/api/auth/*` 与 `/api/health` 外的**所有** `/api/*`（含账号、配置、登录任务、Control 代理、SSE `/api/events`）都要求有效会话，否则 401。
- 会话用 HttpOnly + SameSite=Strict Cookie，HMAC-SHA256 签名，12 小时过期；**退出登录会把世代号 +1**，此前签发的所有 Cookie 立刻失效（实测旧 Cookie 再访问返回 401）。
- 连续 5 次密码错误锁定 30 秒。
- Control API 令牌是**另一个**字段（`controlToken`），只用于请求上游 Control API，与面板访问完全分离；界面上分列在「① 面板访问」「③ 签到运行」两组里。
- 仍保留 `PANEL_NO_AUTH=1` 的免密模式，但此时界面会明确显示「⚠ 已关闭鉴权，任何能访问本端口的人都能读写账号配置」，不再出现与实际不符的「需要令牌」提示。

### 2. 登录成功判定（P1）

改为以会话文件为准，并区分四种终态：

| 终态 | 判定条件 |
| --- | --- |
| `done` | 进程正常退出（code 0 且无信号）**且**所选平台的会话在本任务期间被写入 |
| `partial` | 两端授权时只写入了其中一个平台（界面会指出缺哪个） |
| `failed` | 非零退出码 / 被信号杀死 / 正常退出但没有写入任何会话 |
| `cancelled` | 用户点了「终止」 |

- 判定依据是 `sessions.db` 里该账号该平台的 `updated_at` **严格大于任务开始前的基线值**，任务开始前就存在的旧会话不会被误判为「本次授权成功」。
- 弹窗会逐平台显示「已写入 · N cookies · 时间」或「未写入」。
- 截图对照：`docs/shots/authorize-done.png`（成功）与 `docs/shots/authorize-failed.png`（脚本打印了成功日志、退出码 0，但没写会话 → 仍判失败）。

### 3. 凭据换行注入（P1）

- 所有自由输入字段（密码、TOTP、备用邮箱、代理凭据、邮箱）在写入前拒绝 `\u0000-\u001f` 与 `\u007f`，含换行的密码返回 422。
- 序列化改为与上游 `loadEnvFile` 解析规则一致：仅当值首尾有空白或首尾是引号时才加引号，并选用值里不存在的引号；同时含单双引号时明确报错而不是静默写坏。
- 实测 `p@ss w=rd "#1"` 这类值写入后能被上游解析规则原样读回（`roundtrip_special_characters`）。
- 生成账号区块时会逐行再校验一次，避免任何字段把换行带进文件。

### 4. 仓库结构校验（P2）

- 新增统一的 `inspectBotRepo()`：要求目录存在、是目录、含 `package.json`（且 `name` 匹配 microsoft-rewards-script）、`scripts/main/manualLogin.js`、`scripts/utils.js`。
- 连接、读账号、写账号、删账号、启动登录全部走同一校验；不合法直接 422 并列出缺什么，**不会创建任何文件**。
- 界面先做环境自检，自检不通过就不允许连接，避免「先显示已连接、启动登录才报缺脚本」。

### 5. 自定义 sessionPath（P2）

- 读取上游 `config.json`（`config.json` / `dist/config.json` / `src/config.json`）的 `sessionPath`，按 `path.resolve(仓库, sessionPath)` 与 `dist`、`src` 变体依次查找 `sessions.db`。
- 界面提示会标出当前会话目录，例如 `会话目录 config.sessionPath=custom_sessions`；数据库读取失败会把错误显示出来。
- 措辞已统一为「已保存会话」，不再暗示会话一定有效。

### 6. Control API 状态分级（P2）

`/api/state` 与 `/api/config` 现在返回五态之一，界面按状态显示不同文案与颜色：

- `online` → 绿点「签到接口在线」
- `unauthorized` → 红点「签到令牌无效」（HTTP 401/403）
- `error` → 红点「签到接口异常」（其它非 2xx）
- `offline` → 红点「签到接口异常」（网络不可达）
- `unconfigured` → 黄点「签到接口未配置」，并说明「仅运行签到需要它，账号授权不受影响」

`/api/control/start` 在非 online 时直接返回 503 与具体原因，不再把 401 当成可用。

### 7. 保留指纹设置（P2）

- 编辑账号时 `SAVE_FINGERPRINT_MOBILE` / `SAVE_FINGERPRINT_DESKTOP` 未提交则沿用原值（实测原 `false` 不再被改成 `true`）。
- 表单里新增两个开关，编辑时会回填当前值；新增账号默认勾选。
- 同时保留原有行为：密码、TOTP、备用邮箱、代理留空即保持原值。

### 8. 界面调整

- 入口收敛为**居中单列**（最大宽度 356px）：小图标 + 「欢迎回来」+ 单个密码框 + 一个主按钮 + 条款/隐私弹窗，与参考项目的主流程一致（`docs/shots/unlock.png`）。
- 实例路径、Control API、自检等配置移出入口，放进「首次设置」页与「环境与设置」标签页，日常使用不再被配置项干扰。
- 三类信息明确分区并各自命名：**① 面板访问**、**② 微软账号授权**、**③ 签到运行（可选）**；账号列表标题也从「已绑定账号」改为「微软账号授权」。
- 主流程按报告建议重排：解锁 → 首次检查环境（仓库/Node/依赖/Chromium/构建/会话库）→ 添加账号 → 发起授权 → 显示会话保存结果 → 后续复用。
- 账号行的主按钮从「登录」改为「授权」，弹窗标题为「微软账号授权」，避免与「面板登录」混淆。
- 「退出」现在会调用 `/api/auth/logout`（服务端作废会话）并 `localStorage.clear()`，与文案一致。

### 9. CSS 与响应式

- `max-width 100%;` 已改为 `max-width: 100%;`（全文件已无同类写法）。
- 新增解锁页/设置页/自检清单/授权校验等样式；窄屏（414px）与浅色主题已重新截图复测。

## 四、仍未覆盖 / 已知边界

报告要求「用真实账号验证首次授权 → 会话保存 → 重启 → 复用」，这部分**需要你的真实微软账号**，我无法代跑：

- 自动化回归覆盖了「会话写入判定、重启后读取、再次授权刷新」这条链路（用假脚本写入真实结构的 sessions.db）；
- 但「真实微软登录流程能否走通」取决于你本机的依赖、Chromium 内核、代理与账号状态，请按下面步骤自测。

**你的自测步骤：**

1. `node server.js`，用终端打印的访问密码进入面板；
2. 首次设置页填脚本仓库根目录，确认自检全部为绿（缺依赖就按提示 `npm install` / `npx patchright install chromium`）；
3. 添加账号 → 点「授权」→ 在弹出的 Chromium 里完成微软登录（含二次验证）；
4. 观察弹窗：「移动端 已写入 · N cookies」= 成功；若显示「未写入」会同时给出原因；
5. 关闭面板再启动，账号行仍应显示「移动端 · N cookies · x 分钟前」——这就是可复用状态；
6. 两端都要：选「两端都授权」，若只完成一端，任务会显示 `partial` 并指出缺哪个平台；
7. 建议同时试一次失败路径：授权时直接关掉浏览器窗口，面板应显示失败而不是成功。
