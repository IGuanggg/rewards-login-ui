# 签到工作台与设置

首页提供一键运行全部账号、单账号运行、停止、当前账号/任务、耗时、确认积分、最近一次结果和下一步操作。运行状态取自上游 Control API，任务取自持久化记录。启动请求会立即禁用重复点击；刷新页面可重新读取后台运行状态。积分未知时显示“待确认”，不生成演示记录。

“环境与设置 → 签到设置”展示当前脚本实际支持的 12 类任务开关（缺失的配置项不展示）、搜索/账号间隔、搜索词来源、脚本风控警告处理、跳过无积分任务和每日定时。写入前校验；运行或登录中禁止修改；原配置保存在 bot-config.json.panel.bak，保留敏感字段和未展示的上游配置。修改不会开启并发或改变 Docker 的资源限制。

每日定时保存在面板配置同目录的 schedule.json，优先于 RUN_AT；关闭后不会被环境变量重新开启。按实例时区检查，每日一次，到点浏览器忙碌则记录跳过，当天不补跑。容器到点未运行也不补跑。界面保存后无需重启。部署更新保留现有设置，不自动开启定时。

首次账号登录默认选择两端授权。启动前检查账号、运行依赖和构建产物；没有密码也没有有效会话元信息的账号提示先登录。已有 Cookie 只能证明曾保存登录状态，不能保证微软会话仍有效；实际失效时需要重新登录。

## 旧用户脚本比较

用户提供的脚本为“微软积分商城签到（改进版）3.6.52”，使用 GM_*、浏览器 Cookie 和 crontab 元数据，不能直接作为普通 Node.js 脚本在当前 Docker 中运行。

检查时，它标注的作者仓库 main 分支 sc/微软积分商城签到.user.js 声明 3.6.10。无法仅凭改版数字认定它是官方最新版，也未进行真实账号任务成功率对比。当前 Docker 上游为 4.3.2，与检查时官方 v4/package.json 的版本号一致，但版本号一致不代表提交完全一致。

值得借鉴的是任务/配置分组、间隔可调和通知入口。当前先接入已验证的原生任务、节奏和定时功能；通知推送尚未增加面板配置入口。国区锁在旧脚本中的含义是按 IP 检测停止，不是切换地区；当前没有加入该功能。旧脚本离线搜索词含随机后缀，当前采用上游的本地词库选项，不照搬该生成方式。授权码不手动展示或复制，继续使用已部署的远程浏览器登录与会话持久化。

另一个具体问题是搜索间隔文案：输入 30 秒，代码按 span−15 至 span+15 随机，实际可能只有 15 秒。因此不能把它理解为搜索间隔始终至少 30 秒。当前面板直接展示最小和最大值，避免这种歧义。
